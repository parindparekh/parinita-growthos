# Sign-in through Parinita Witness

GrowthOS does not need a commercial identity provider. Set `IDENTITY_PROVIDER=witness` and it uses Witness for
both console sign-in and API tokens. Underneath it is the same standard OpenID Connect described in `SSO.md`; the
Witness profile only changes where roles are read from and what the sign-in button says.

The profile assumes what the Witness architecture specifies: a Keycloak-based identity plane. If your Witness
build exposes OIDC differently, leave `IDENTITY_PROVIDER` empty and set the claim names yourself.

## In Witness (realm administrator)

1. Create a client `growthos`: standard flow on, PKCE `S256`, client authentication on (confidential).
2. Valid redirect URI: `<PUBLIC_BASE_URL>/auth/callback`.
3. On that client, create the roles `editor`, `approver`, `publisher`, `auditor`, `admin` and assign them to
   people (directly or through groups). `admin` does not include `approver`; assign it deliberately.
4. For services that call the GrowthOS API or `/mcp` with their own tokens, add an audience mapper so their
   access tokens carry `aud: growthos`.

## In GrowthOS (`.env`)

```
IDENTITY_PROVIDER=witness
OIDC_ISSUER=https://witness.example.internal/realms/parinita
OIDC_CLIENT_ID=growthos
OIDC_CLIENT_SECRET=...
SESSION_SECRET=<generated by deploy.sh>
```

## How roles are resolved

| Where the value sits in the token | Becomes a GrowthOS role when |
|---|---|
| `resource_access.growthos.roles` (roles of the GrowthOS client) | it is one of the five role names |
| `realm_access.roles`, `roles`, `groups` | it is listed in `OIDC_ROLE_MAP`, or it carries `OIDC_ROLE_PREFIX` (e.g. `growthos:approver`) |

A realm-wide role or group that merely happens to be called `admin` grants nothing. Only roles scoped to the
GrowthOS client, mapped explicitly, or prefixed count.

Keycloak puts roles in the access token and, by default, not in the ID token. At sign-in GrowthOS therefore also
reads the access token it receives from the token endpoint, and trusts it only if it is signed by Witness,
unexpired, issued to the `growthos` client (`azp`) and for the same subject as the ID token.

## What this gives you

- The audit trail names the Witness identity for every approval, withdrawal and sentence decision.
- With Witness on, API keys cannot approve (`APPROVAL_REQUIRES_SSO`), so every signature is a Witness-authenticated person.
- Agents and services authenticate to the API and to `/mcp` with Witness-issued tokens and get exactly the roles
  Witness assigns them. No MCP tool can approve, whatever the role.
- `TRUSTED_INTERNAL_HOSTS` lets GrowthOS reach Witness-fronted internal services on private addresses.

## Not done here

- **Not tested against a Witness tenant.** Verified against a mock OIDC provider issuing Keycloak-shaped tokens
  with real RSA signatures. Run the Day 1 SSO lines of the acceptance checklist against your realm.
- GrowthOS does not send its privileged actions to Witness as events, and does not ask Witness for a per-action
  authorization decision. Both need a Witness API contract I do not have; the audit chain (`/v1/audit`) is the
  feed to build that on.
- No session revocation from Witness before the GrowthOS session expires (`SESSION_TTL_SECONDS`, default 8 h).
